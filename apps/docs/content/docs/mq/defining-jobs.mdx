---
title: Defining Jobs
description: Declare immutable queue identities, codecs and payload versions.
---

A queue is an inert namespace. A Job identity is the literal
`queue + name + version` tuple; JavaScript function names are never used for
persistence or routing. Defining a Job does not resolve a Service, open a
connection or register a Worker.

```ts
import * as z from 'zod'
import { Codec, Queue, Retry } from 'better-effect-mq'

const SendEmailPayload = z.object({
  to: z.email(),
  messageId: z.string().min(1)
})
const SendEmailFailure = z.object({ code: z.string().min(1) })

const Emails = Queue.define('emails')
const SendEmail = Emails.job('send-email', {
  version: 1,
  payload: Codec.standardSchema({ schema: SendEmailPayload }),
  result: Codec.void,
  failure: Codec.standardSchema({ schema: SendEmailFailure }),
  defaults: {
    attempts: 5,
    backoff: Retry.exponential({
      initialDelayMs: 1_000,
      maxDelayMs: 60_000,
      maxAttempts: 5
    })
  }
})
```

`Codec.standardSchema` is the recommended persistence-boundary codec for a
provider-backed schema. The Zod 4 schemas above are Standard Schema-compatible
and can be shared with the rest of an application; `better-effect-schema` adds
normalized failures and schema-backed classes when those are useful. Primitive
codecs remain convenient for primitive values. `Job.PayloadInput` describes the
codec input; `Job.Payload` is the decoded value received by a handler.

## Trusted JSON escape hatch

`Codec.json<T>()` is an intentional simple JSON escape hatch, not the default
for boundary examples. Use it only when the value is already trusted and
JSON-safe and there is no meaningful runtime validation to perform.

Keep a new Job version when a persisted payload or result contract changes:

```ts
const SendEmailV2 = Emails.job('send-email', {
  version: 2,
  payload: Codec.standardSchema({
    schema: z.object({ recipient: z.email(), body: z.string().min(1) })
  })
})
```

A local `JobRegistry` can accept multiple versions for a Worker claim. It is
not a global handler registry. Version changes and upcasting are application
policy: keep old codecs available for records that are still in flight, and
remove a version only after its persisted records are retired.

Metadata is bounded string data. Do not put connections, requests, live
`Error` objects, lease tokens or arbitrary causes in a Job record.
