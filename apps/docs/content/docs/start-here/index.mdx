better-effect is a small TypeScript architecture for `better-result` workflows. Start with the
short path below: define a Service, compose a Layer, run the program, and let Scope own anything
that needs cleanup.

## Choose a path

- **I am new to better-effect:** read [Getting Started](./getting-started), then [Services](../core/services).
- **I need a durable queue:** begin with [MQ](../mq), then pick a storage adapter in [Integrations and adapters](../integrations).
- **I am integrating an existing system:** open [Integrations and adapters](../integrations) and choose the boundary you already operate.
- **I need reliable post-commit publishing:** read the [Outbox guide](../outbox).

The docs use one vocabulary throughout. Application code defines jobs and handlers with
`better-effect-mq`; adapters only provide persistence through Layers.
